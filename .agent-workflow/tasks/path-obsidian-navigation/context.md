- 后续用户指出上下竖线错位，并进一步用红框澄清顶部文件/搜索下方需要横线：当前保留 WorkspaceHeader 的 1px 底边框并与 TabBar 对齐，仅去掉文件工具栏下方横线，工具栏高度仍为 39px。拖动竖线右对齐顶部边界，折叠时隐藏多余右边框。

- 专项及完整编辑回归在 1440 明亮/1024 暗色均通过，覆盖外层/内层取消、撤销/重做、点击代码与长引用第二段、阅读/IR/SV/快速文件切换及 mocked PUT。嵌套引用按 Lute 原生规范化为 `>>` 或 `> >`，测试核对层级，不强求字节级排版。详见 `runs/2026-10-10-quote-prefix.md`。

## Tab layout and menu follow-up (2026-10-10)

- 用户要求标签默认长度统一，拥挤时平滑缩短，取消横向滚动条。TabBar 按实测栏宽均分文件和知识图谱标签宽度，默认上限 200px，新增和恢复宽度使用 200ms ease；尊重 reduced-motion。
- 用户进一步纠正下拉交互：箭头固定在标签栏最右侧，点击仅打开下拉菜单；选择“全部关闭”才关闭全部文件及图谱标签。`+` 仍紧随标签用于新建。
- 为两个按钮预留 64px；关闭全部使用单个 Redux action 清空 openTabs/activeTabId，并进入原保存队列。主页面同时清空图谱及导航历史，避免空白状态经返回按钮恢复旧文件；不删除文件。
- 用归一化带结尾换行的隔离笔记验收末次输入与关闭后刷新；页面和 API 均不触碰真实用户数据。
- 用户指出切到其他页面再返回不应有过渡。真实路由回归先失败：两标签各触发 tabEnter，标签容器触发 width transition。原因是每次重新挂载均套用无条件入场动画，初始宽度/异步恢复也参与过渡。Path 按本次用户加载完成状态传递 restoring；TabBar 在恢复阶段无宽度动画，提交测宽布局后才启用后续过渡，仅新插入的标签标记入场。首次加载和 2/24 个标签离开再返回均不动画，新增/关闭动画和 reduced-motion 检查通过。

## Sidebar motion follow-up

- 用户要求侧栏开合增加过渡并加宽默认尺寸；实施选择为 240px → 300px、200ms ease。
- 顶部宽度不能在动画期间经 React 状态逐帧回传，会慢一帧。改为 ResizeObserver 绘制前同步容器 CSS 变量；拖动关闭过渡，并以实际宽度接管正在进行的动画。
- CSS max-width 立即约束窗口变化，保留桌面 420px 主区和 560px 侧栏上限；系统减少动态效果时直接开合。
