# 已确认存储方案的实施设计

## 使用效果
简历与学习规划均由服务器保存正式版本，浏览器缓存用于恢复未确认编辑。用户可在学习规划或简历界面选择一次个人资料目录，之后两模块修改自动生成本地副本。目录未选择、取消、权限失效或写入失败均不阻断服务器保存。

## 简历服务器保存
新增 resume_workspace，每用户一条 JSON 简历集合、revision 和更新时间。GET/PUT /resume/workspace 从登录身份确定账号；旧版本 PUT 返回 409。复用前端 WorkspaceSaveQueue，保留失败草稿并显示重试。发生冲突时显式恢复，保留远端并把本地不同简历另存副本。

首次读取服务器没有简历记录时，迁移当前账号已有 localStorage 简历；服务器已有记录则以服务器为准。首次迁移遇到相同 ID 的不同内容时生成本地恢复副本，不能直接覆盖。服务器成功确认后才标记迁移完成。已有空云端集合表示用户删除过简历，不能自动用已迁移的旧缓存复活。

## 个人目录副本
浏览器 File System Access API 选择读写目录，句柄按账号存入 IndexedDB。写入所选目录下 KNOWVIA/user-账号/，学习规划包含 workspace.json 和 Markdown 笔记，简历包含 resumes.json 和每份简历 JSON。文件名使用清理后的名称和稳定 ID 后缀，防止非法路径和同名覆盖；恢复时目录结构与简历全部内容以集合 JSON 为准。

服务器和目录两条保存链路独立。本地集合同时标注服务器版本与是否已确认，离线编辑也可形成草稿副本。写入按最新快照串行执行，旧任务不得覆盖新编辑；切换账号或换目录后停止后续旧目标写入。后台只查询权限；恢复权限由用户点击触发。取消选择保留原配置，解除绑定只移除句柄，不删除电脑文件。

本地副本仅从平台向目录写入，不自动反向导入。用户手工改动已有文件时保留该文件，另存平台副本并提示；重命名或删除的旧文件保留为历史副本，当前列表以集合 JSON 为准。

## UI 与验收
两模块共用 PersonalStorage 配置弹窗；简历列表和编辑页显示云端保存状态、重试及冲突恢复。弹窗只说明是否授权、目录名和独立备份状态，不展示内部技术细节。

验收覆盖旧缓存迁移、清空浏览器后服务器恢复、并发/旧版本保护、不同账号隔离、编辑后导航、目录取消/无权限/不支持、同名与非法文件名、最新编辑保留和双模块实际文件输出。数据库使用临时隔离库；目录写入使用受控测试空间，不写用户真实资料。Native OS 选择框如不能自动化需明确区分模拟选择与真实文件写入。
