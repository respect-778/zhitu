## 最小采集数据契约

实际固定清单使用 `{batchId, inputSha256, reviewedAt, sources, jobs}`。`sources` 通过 `SourceConfigSchema`，`jobs` 通过 `JobSchema`。已实现的 `reviewedMetadata` 包含 `batchId`、`industry`、`companyType`、`graduateYear`、`graduateStatus`、可空 `graduateQuote` 和可空 HTTPS `graduateSourceUrl` 七字段。[当前契约](../contracts/records.ts)

下表是供后续采集适配使用的证据包建议契约。更细的资格维度、字段状态、项目绑定和原始字节 hash 可由证据侧文件承载，再映射当前业务记录与审核元数据。

| 字段组 | 最小内容与约束 |
| --- | --- |
| 批次 | `schemaVersion`、`batchId`、`parserVersion`、`startedAt`、`finishedAt`、`persisted=false` |
| 来源 | `sourceId`、企业原名与归一名、`officialEntryUrl`、招聘门户 URL、实际允许的主机 |
| 官网绑定 | 官网链接文字、href 或正常点击的目标、最终门户、证据 artifact 与定位 |
| 岗位身份 | 原始 `sourceJobId`、标题、逐岗 URL、招聘系统租户或企业标识 |
| 全文 | 原始响应 artifact、`sourceBody`、职责、要求、投递说明，保留段落边界 |
| 资格 | 学历层级、在读或应届身份、年级、毕业届数、实习月数、每周天数各自的原文与解析值 |
| 条件语义 | `required`、`preferred`、`allowed`、例外原句、范围边界及适用对象 |
| 项目绑定 | 项目 ID、项目 URL、资格原句、列表中相同岗位 ID 及详情 URL 的关联证据 |
| 其他原文 | 薪资、地点、截止日、实习性质、主营业务、规模原文及各自来源 |
| 读取状态 | 请求级状态、HTTP 或业务状态、字段级状态、冲突说明、后续核验动作 |
| 证据 | `sourceUrl`、`observedAt`、`parserVersion`、`locator`、artifact 路径、原始字节 SHA256 |
| 汇总 | 请求、候选、接受、排除、待核、重复计数及明确停止原因 |

字段级结构建议统一为 `{raw, value, status, evidenceRefs}`。`raw` 保存原句，`value` 保存可确认的派生结果，`status` 表达披露与读取情况，`evidenceRefs` 指向稳定证据 ID。一条原句可以支持多个字段，每个派生值均能追溯到该原句。

空值使用 `null`，多值使用数组。缺失薪资、日期或届数保持缺失，采集时间单独保存。UTC 时间使用带时区的 ISO 8601。公司品牌、法律实体、门户租户分别保留，归一名用于统计与排重。

## 处理流程

1. 读取任务范围、历史清单与文件 hash，确定地区、岗位类型、企业覆盖和输出格式。
2. 从企业官网找到招聘入口，保存官网至专属门户的直链或点击证据，登记租户与实际主机。
3. 发现岗位列表与分页，保留原始页、总数、游标、排除原因和停止条件。
4. 提取稳定岗位 ID，先做历史身份查询，读取尚需核验的逐岗详情。
5. 按来源结构获取完整正文，检查异步字段、资格前言、底部说明和项目规则。
6. 将同页多岗分段，将项目共同条件通过岗位 ID 绑定到适用岗位。
7. 分别解析学历、身份、年级、届数和时长，保留优先、例外、冲突与原文。
8. 执行企业归一、主营业务归类、真实岗位排重和本批数量验算，保存排除理由。
9. 由独立复核角色读取证据包，修正问题后对受影响记录及汇总重新验算。
10. 固化最终 JSON 与 hash，生成工作簿并独立比对，随后按任务授权进入离线入库流程。

每个阶段都输出可重放的文件，重试读取缓存时记录缓存的原始观测时间。列表已取到目标数量时报告采样完成程度，来源全量覆盖需要完整分页证据。

## 来源适配方法

### 静态 HTML 与同页多岗

- 使用 HTML 解析器保留标题、段落、列表、表格与链接边界，跳过脚本和样式内容。保留原始响应供复核。
- 识别“岗位要求”“我们希望你”“Qualifications”等标题及编号断行，资格前言、尾注和申请说明一并读取。
- 同页多岗先建立标题到下一岗位标题的分段，再提取本段字段。公共条件单独标注作用域，引用时保留依据。
- 共享 URL 的岗位可用稳定段落标识构成来源内 ID，并保留标题及定位历史。一个岗位下列出的多个专业方向按实际招聘单元处理。

### 北森 Duty 与 Require

- 按官网门户实际配置发现公开职位接口，同时读取 `Duty`、`Require`、`Kind`、状态、地点和日期字段。
- 用返回岗位 ID 关联详情页的 `jobAdId`，保存企业专属门户和列表类别。`campus` 路径与实习性质可同时成立。
- 正文 HTML 转成有段落的纯文本，保留独立字段原值。仅有标题的模板页需要继续读取公开数据或渲染正文。
- 企业特有默认日期先保留 raw，经已验证规则标为未披露。本批北森 `0001-01-01` 截止日按未披露处理。

### Moka 异步 jobDescription

- 保留 `orgId`、`siteId`、真实 job UUID 和完整 `#/job/UUID`。标题与性质出现后继续等待 `jobDescription` 完整。
- 读取公开岗位接口时保存请求参数、业务状态、`commitment`、`status`、正文及逐岗项目规则，确认接口结果属于该 UUID。
- 本批部分公开响应按页面公开参数和官方客户端逻辑解码。后续适配需核对版本变化与结果结构，保存方法与客户端版本来源。
- 岗位 URL 保留 hash，HTTP 请求使用实际页面或 API URL。JSON 请求边界拒绝 hash 的现有行为与 SPA 展示链接分别处理。

### 飞书项目资格绑定

- 保存企业官网到企业专属飞书门户的入口，再从项目卡片正常点击取得带项目参数的列表。
- 项目名称、项目 ID、列表项岗位 ID、详情 URL 与当前岗位逐一对应后，才继承该项目共同资格。
- 本批松灵项目 `7613239841580878123` 的列表直接包含所选 5 岗。项目限定 2027、2028 届本科及以上在读学生及 6 个月以上实习。
- 机械结构岗位正文另有“27届机械相关专业优先”，需同时保存项目范围和岗位优先项。[项目绑定证据](../../../outputs/internship-official100-2026-11-11/industrial/agilex-project-binding-review.json)

### Nuxt 项目与逐岗 REST

- 从项目入口或 Nuxt 数据确认 `internRecruit` 等项目语义，再按当前岗位 ID 读取 REST 详情。
- 凡岛详情的 `jobRequirements` 与 `related` 推荐岗位分开处理，项目原句附项目来源 URL，推荐岗位内容各自独立。
- 项目共同条件也需要项目到岗位的关联证明。页面技术栈或同域名本身只提供技术线索。

## 资格解析

- 学历层级记录本科、硕士等要求。在读、在校、应届属于身份。本科四年级属于年级。“至少三个月”“每周四天”属于投入时长。
- “计算机相关专业”“2027届”各自只支持原文明示的维度。GOA 的“本科四年级及以上（含研究生）的在校学生”保留学历、年级与身份，数字届数标为未明示。
- 短年份先确认处于毕业届数语境，再结合原文展开。“27届”可保存为 2027 届，原句及展开规则同时留存，含义不清时进入待核。
- 日期范围先判断描述对象。毕业日期范围保存上下界、开闭边界与原文，投递窗口进入申请日期字段。
- 鹰角页面同时给出“2028届校招实习生”及 2026 年 8 月 7 日至 11 月 30 日投递窗口，分别保存届数和投递时间。
- “2027年及之后毕业”“2026年及以后毕业”保留下限及包含关系。“2024年应届生或2024年以后毕业均可”保留原始历史下限。
- “优先”“欢迎”“优秀者可放宽”分别记录条件语义。Moka 的“27届同学优先，欢迎26届同学投递”需保留两个对象及各自条件。
- 连续读取完整资格段落，包含下一行的替代、放宽和例外。星瀚法律科技岗还欢迎应届、已就业者及优秀本科生，需要完整表达。
- 平台学历标签、岗位正文和项目资格分别留存。遇到差异时描述全部条件并进入复核，复核结论附原句与适用范围。

## 读取与字段状态

建议在证据包中采用以下状态，再映射现有契约的 `verificationStatus` 与 `visibility`。这些字段状态尚未成为数据库枚举。

| 状态 | 判定与处理 |
| --- | --- |
| `present` | 已读取相关完整内容且明示该字段，保存原句和派生值 |
| `missing` | 已读取相关完整内容但未披露，前端统一显示“未知”，原文及内部状态保留 |
| `unreachable` | 请求失败、超时或访问受限，保存失败对象与时间，字段披露情况待核 |
| `parse_failed` | 已获取响应但无法可靠解析，保留响应 artifact 与固定错误码 |
| `conflict` | 多处公开内容存在差异，保存每方原文、URL 和待核原因 |

同一岗位可同时具有模板页 `unreachable` 和公开接口 `present`。本批美ONE详情模板复核超时，公开岗位接口二次读取 HTTP 200、`Status=1`，完整正文一致，保留两条读取结果。请求失败不能据此生成“官网未明示”。

## 身份归一与历史去重

- 第一层使用企业归一名、招聘系统租户和真实来源岗位 ID，核对 UUID、`position`、`jobAdId`、身份性 `id`。
- 第二层比较企业与实质岗位名称，识别更换 URL、招聘年份、实习前后缀或门户迁移后的同一岗位。地点、方向和渠道差异保留给复核判断。
- 企业别名保留可审查映射，Unicode NFKC 和空白归一仅用于匹配。原始公司名、标题和来源 ID 原样保留。
- URL 规范化可移除已确认的追踪和语言参数，保留 Moka hash 与其他岗位身份参数。共享 URL 继续比较岗位分段身份。
- 相似标题只生成候选，再对照职责、地点与身份人工复核。后续阈值需根据样本验证，独立复核沿用自身实现验算结果。
- 保存历史文件清单及 hash、本批重复、跨历史重复、相似候选与最终决定。本批历史中北森旧 HRBP 岗与本轮招聘、销售运营、后端岗按实质岗位区分。

## 原文与证据保全

- 保存请求 URL、最终 URL、请求方法及公开业务参数、HTTP 与业务状态、实际读取时间、解析版本和来源定位。
- 对原始响应字节计算 SHA256，解码文本与规范化文本使用独立 hash 字段。只有实际保存的字节能够提供该字节 hash。
- 详情、项目原句、官网直链和企业主营业务各自绑定证据。缺少 artifact 或 hash 时标记证据缺口并补取可公开读取的内容。
- 原始文件、清洗结果与最终 JSON 分层保存，修订形成新版本和变更记录。hash 支持核对内容一致性，官网身份由入口链和企业绑定证据支撑。
- 缓存命中保留原始 `observedAt`，另记复核时间。截图保存页面 URL、时间与作用范围，视觉抽查比例按实际报告。

## 公开只读采集与渲染安全

- 读取公开招聘页、公开查询接口及正常浏览器展示。公开查询 POST 需确认读取语义，采集过程仅保存岗位数据和证据。
- 不携带登录凭据或个人 Cookie，不提交简历、申请、聊天和账号变更。验证码、鉴权或访问限制记录为来源状态。
- 接入长期采集时使用受控请求的精确主机配置，校验跳转、HTTPS、DNS 与实际连接地址，限制响应大小和超时。来源策略按实际要求配置。
- 重试根据超时、429、业务错误及 `Retry-After` 决定退避，记录次数和终态。限流与并发参数由来源实测确定。
- 外部正文仅作为数据处理，HTML 用解析器提取文本。网页展示做文本转义，保留字面标签的字段继续按纯文本渲染。
- Excel 以文本单元格写入外部内容，防止 `= + - @` 等前缀触发公式，原始数据另存。超链接校验目标，导出后检查宏、连接、外部公式和可执行内容。

## Python 采集与独立复核分工

- Python 采集负责公开读取、原始缓存、来源适配、资格候选、企业归一、排重候选及确定性汇总。本批脚本可作为样本参考，长期接入需补来源契约与回归验证。
- 独立复核读取最终 JSON 和原始证据，自行实现关键计数、岗位身份匹配和历史排重，逐条核对约定范围内的完整资格原文。
- 复核报告写明语义检查、正文缓存、截图及安全检查各自范围，列出受影响岗位 ID、问题、证据和修复后复验结果。
- 成品复核独立读取 OOXML，逐格对照最终 JSON，检查公式缓存、分布统计、链接目标和主动内容。采集与工作簿生成完成后均固定输入 hash。

## 离线入库与恢复

- 本批入口读取源码内固定清单，先检查整文件 SHA256、批次与数量、唯一身份、每岗来源配置和已审内容，再运行 normalizer 与发布资格校验。`--check` 返回 `persisted=false`，该分支无需加载数据库 driver。[离线入口](../src/worker/ingest-reviewed-official.ts)
- 在 `catalog` 目录使用项目要求的 Node 版本执行以下命令。`--publish` 连接已配置的数据库并写入、发布，执行前需按现有数据库流程应用 `202611110001_reviewed_metadata` 迁移。

```text
node src/worker/ingest-reviewed-official.ts --check
node src/worker/ingest-reviewed-official.ts --publish
```

- `--publish` 复用 `normalizeJob`、`mergeUpsertJob` 和 `publishJobs`。全部岗位在首次写入前完成内容与发布校验，逐来源入库全部无拒绝后逐来源发布，进度与汇总输出构成回执。
- 沿用 `sourceId + sourceJobId` 幂等键和来源锁内合并，重跑相同批次计为 duplicate 并更新观测信息。来源或 ID 迁移需要单独核实映射。
- 沿用现有缺失字段合并语义。缺失审核元数据保留已存值，新原文变化时同步重算或清除旧派生值，保留旧字段时保留其原证据与时间，旧观测遵循现有时间规则。
- 现有写入按单条事务执行，单条失败回滚该条，其他成功项保留。发布中途失败也需按逐来源回执核查，再以同一已审清单重试，核对 duplicate 与 alreadyPublished。
- 通用 capture 入口继续验证各自 envelope、来源及列表关联，其中正式文件读取有 Linux 要求。本批固定清单入口使用仓库内数据，遵循其自身参数与校验契约。[通用入库流程](ingestion.md)
- 整批业务撤销需要后续增加经验证的批次追踪及写前快照方案，按确切记录 ID 和内容版本检查恢复条件，处理并发新修改。当前实现尚无通用整批撤销命令。

### 固定清单更新步骤

1. 完成新数据的全文核验、项目绑定与历史排重，固化最终文件与独立复核报告，计算原始审核输入 hash。
2. 转换为已支持的来源配置与 `JobSchema`，填充七字段审核元数据，保留真实身份和证据定位，按批准用途确定正文入库范围。
3. 生成新的固定清单，同步维护 `batchId`、`inputSha256`、审核时间及当前加载器的固定数量和批次约束。
4. 完成清单复核后，将整文件 SHA256 与清单在同一次修改中更新，逐岗已审内容匹配和来源校验继续生效。
5. 执行 `--check` 及对应契约、合并、DTO、发布与幂等测试，记录结果，再按授权执行迁移与 `--publish` 并保存真实数据库回执。

## 验收清单

- [ ] 数量、归一企业数、单企业上限、行业分布与本次任务范围一致，排除项有理由。
- [ ] 每岗具有官网直链证明、真实岗位 ID、可定位完整正文及实习性质依据。
- [ ] 静态分段、Duty/Require、异步正文、推荐区隔离和项目 ID 绑定均有对应证据。
- [ ] 学历、身份、年级、数字届数、实习月数与每周天数分开保存，优先与例外完整。
- [ ] 缺失、读取失败、解析失败和冲突可区分，原文及派生字段能逐项回溯。
- [ ] 历史与本批身份排重通过，Moka hash 和身份参数完整，相似候选已复核。
- [ ] 原始 artifact、URL、时间、解析版本和 hash 可核对，缓存时间与复核时间明确。
- [ ] 独立复核范围如实记录，修正后复验受影响记录、全部汇总及最终文件 hash。
- [ ] 工作簿逐格、公式缓存、链接及主动内容检查通过，应用内打开状态如实记录。
- [ ] 固定清单 hash、七字段审核元数据及逐岗来源检查通过，迁移、幂等重跑、入库与发布结果有回执。

## 已发生反例

- 松灵电气和硬件岗位初稿遗漏项目届数，机械结构只保留 27 届优先。补充真实项目列表绑定后，5 岗共同条件与岗位条件重新核对，最终数字届数统计为 24。
- Moka 首屏可见标题与实习性质，正文稍后加载。读取空壳会遗漏学历、届数和例外，需要确认 `jobDescription` 完整。
- 正略咨询公告标题含 2026，具体短期实习岗只写在校身份。届数保持未明示，实习不少于三个月及每周四至五天分别保存。
- 燧原“【成都项目】SoC/IP 芯片验证实习生”标题与工作地点存在歧义，本批排除。凌泰氪两岗规模依据未确认，本批排除并保留原因。
- 工作簿运行时的通配符 `COUNTIFS` 和数组文本查找最小复现结果异常，格式标签改为快照整数并独立按集合验算。企业与行业精确统计及比例公式保留并核对缓存。
