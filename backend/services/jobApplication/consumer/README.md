# KNOWVIA 同浏览器岗位与聊天记录读取

官网入口为 <http://127.0.0.1:5186/applications>。默认展示数据库岗位，BOSS、智联实时读取支持桌面 Chrome、Edge。

## 智联招聘

选择“智联招聘”后连接当前浏览器，在智联搜索页完成登录。搜索会使用智联页面自身的城市、学历和工作性质筛选事件，后续岗位通过原生滚动加载事件读取。岗位详情优先复用登录后列表中的完整正文，缺少正文时在搜索页选中对应岗位读取详情区域。来源访问限制和登录提示会暂停读取并保留进度。

0.7.2 支持复用同一浏览器其他窗口的已登录智联搜索页，并保持其他官网任务和隐身窗口的隔离。站内筛选需等待新列表成功替换后才读取，平台请求失败且保留旧列表时暂停，明确恢复才重新尝试。智联网页自身的 3 秒请求超时也会保留旧列表，读取器会识别这种情况。

官网复用统一的筛选、薪资原文排序、结果表格、手机卡片和勾选操作。BOSS 与智联各自保存查询、岗位和续读位置，IndexedDB 键分别为 `latest`、`latest:zhaopin`，旧 BOSS 缓存继续恢复。“全部”合并数据库与两个平台的浏览器结果。岗位身份由平台与来源岗位 ID 共同确定，智联投递地址来自该岗位的 `positionURL`。

智联批量操作当前接入约定的准备状态接口。平台代码为 `zhaopin`。连接、读取、筛选及缓存使用页面数据，无需 AI 配置。

Agent 开发搜索按 Agent 主题检索，再用标题和正文职责核对开发方向。保留正文实际从事 Agent 开发的 Java、软件开发等岗位，并展示对应职责原文；排除仅在任职要求中提到使用 AI 工具的岗位。缺少正文的候选先自动补全再判断，旧浏览器缓存同样重新核对。城市、学历与实习条件仍使用用户选择。

0.7.5 兼容智联原生地址中的 el、et 参数，以及主题词的大小写。已符合条件的原生页面复用当前列表。2026-11-11 同样的深圳、本科、实习条件下，“agent开发”原查询返回6条，“Agent”主题查询返回12条，职责核对后保留8条；刷新官网后8条及筛选恢复。本轮10项智联专项及生产构建通过。

2026-11-11 本地验证完成，岗位相关 96 项回归及生产构建通过，其中智联专项 7 项。真实官网入口读取“产品经理、深圳、本科、实习”9 条岗位，9 条正文完成核验，刷新后岗位与筛选恢复。来源网页请求超时的暂停、旧结果拒绝和明确恢复均已检查。

## 工作台沟通与投递记录

工作台 `/workspace/messages` 在 0.6.x 支持手动消息发送、BOSS 当前附件简历发送及平台回执核对。`chat-actions.js` 复用原平台编辑器、发送和简历确认控件，消息送达、失败、简历交换请求与未确认结果分别呈现。相同操作标识重复请求复用结果。收件会话和账号在执行前核对，官网草稿与平台原有草稿分别保留。HR 回复变化通过扩展消息通知工作台，平台折叠后保留绿点。

投递记录通过 BOSS 自身的 `/wapi/zprelation/resume/geekDeliverList` 读取，包括同账号其他设备同步到平台的记录。官网按账号和岗位标识保存、去重与分页，平台已投递记录作为成功依据。真实账号已读取 15 条，手机端新增与发送使用合成链路核验。用户本轮选择先完成代码与合成测试，真实发送留待后续验证。

## 全部来源与数据库检索

- 默认勾选“全部”，通过现有 `/api/catalog/v1/jobs` 查询已发布岗位。该来源包含企业官网与已收录的招聘公告，并合并当前网页内已读取的 BOSS 结果。
- 企业官网使用 `sourceKind=enterprise`，人社使用 `sourceKind=announcement` 查询已收录公告。来源切换保留数据库搜索条件并回到第一页。当前可信来源仅有腾讯企业官网，人社公告等待采集与发布后展示。
- 数据库结果优先排列，本次 BOSS 结果接在数据库结果之后，统一每页 20 条。最新一次平台查询结果保存至当前浏览器 IndexedDB，重新打开页面时恢复岗位、筛选与续读位置。关键词、城市、学历、用工与招聘渠道筛选同时核对两类结果，缺少明确类型的记录按未知处理。
- 选择 BOSS直聘，在同一浏览器连接并登录后读取新岗位，再选择“全部”合并查看。其余主流平台按各自适配进度接入。
- 数据库查询失败会显示错误，并保留本次 BOSS 结果供浏览。数据库检索由现有独立 catalog API 提供，官网使用只读接口。
- 数据库与 BOSS 结果共用 `JobResults.tsx`，列顺序为职位、薪资、公司名称、企业类别、行业类别、城市、学历要求、届数、截止时间、投递地址，手机端使用同一套卡片。
- 列表加载时自动通过现有只读岗位接口获取准确跳转地址，每页最多四个并发请求，切换查询时取消旧请求。投递地址直接打开该岗位的官网、公告或明确的申请页面，链接暂未取得时显示未知。
- 学历采用规范化学历值显示，如本科、硕士。缺少规范化值时，只接受简短且明确的学历文本。完整原文保存在原记录中。未提供的行业、届数显示未知，截止时间未提供时显示无。

## 批量操作入口

BOSS 列表左侧提供一键打招呼，全部与企业官网列表提供一键投递和直接可见的岗位勾选。选择岗位和已有简历后，点击一键投递即开始填写。支持 Moka、飞书招聘和北森的已适配企业申请表，官网完成登录后自动继续。歧义、已有冲突、缺少资料及未适配控件会逐项提示，最终提交由用户在企业官网确认。支持全选本页、跨页保留和清空选择，修改查询条件或切换来源时清空选择。接口与缓存说明见 [job-actions-contract.md](docs/job-actions-contract.md)，多系统验证范围见根目录 outputs/official-autofill-multiats-2026-11-11/plan.md。

## 本地安装与启动

### 官网邮箱投递

根目录另执行 `npm run applications:api`，邮件服务仅在 `127.0.0.1:5199` 监听，官网通过同源 `/api/applications/v1` 连接。当前会话已启动该服务。邮箱投递与官网填表共用岗位和简历选择入口，首批已核对德琪、智汇元的招聘页邮箱。

在邮件区域选择 QQ 或网易163 发件服务，填写自己的邮箱与 SMTP 客户端授权码，选择当前版本的 PDF 或 Word 简历附件。核对可编辑主题和正文后点击发送邮件。发件授权码在每次尝试结束后清空，应用保存操作ID和状态回执。结果待确认时先查询状态并核对邮箱回执，明确失败后通过“准备重新发送”发起新的操作。

收件人依据来自公开招聘页，完整来源和验证范围见根目录 `outputs/application-channels-2026-11-11/plan.md`。其他招聘站的 API 按各站点实际接口继续接入。当前简历 PDF 导出沿用简历模块的打印导出入口，邮件附件由用户确认当前文件。

### 浏览器助手

1. 根目录 `D:/knownai` 执行 `npm run dev`。
2. 在将要使用官网的浏览器里打开扩展管理页：Chrome 输入 `chrome://extensions`，Edge 输入 `edge://extensions`。
3. 开启开发者模式，点击“加载已解压的扩展程序”，选择 `D:/knownai/ai-job-application/consumer/extension`。不选上一级 consumer 文件夹。
4. 在这个浏览器打开官网，选择“BOSS直聘”后点击“连接 BOSS”。BOSS 会在同一浏览器、同一窗口的新标签页打开，使用该浏览器的登录状态。
5. 用户完成登录或人工验证后回到官网，选择条件并搜索。首次从旧独立 Firefox 迁移时，需要在当前浏览器登录一次；不会复制旧浏览器 Cookie。

官方扩展加载说明：<https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked>。

内置预览浏览器、Safari、Firefox 未提供此次扩展安装包，不能承诺任意浏览器兼容。页面会提示用 Chrome/Edge，不能静默回退到独立 Firefox。正式域名上线前需更新允许的来源并走浏览器商店发布流程。

## 运行结构

- `src/JobSearch.tsx`：官网样式的搜索页、来源卡片、桌面表格和手机列表。
- `src/CatalogJobSearch.tsx`、`catalogClient.ts`、`catalogViewModel.ts` 提供数据库查询、来源筛选及本次浏览器结果的合并展示。
- `src/JobResults.tsx` 是全部来源结果表格、外部岗位链接和手机卡片的共同入口。
- `src/useBossNavigation.tsx` 与 `extension/navigation.js` 管理用户主动打开 BOSS 岗位的状态、暂停读取和显式重试。
- `src/api.ts` 管理搜索任务、分页、停止、去重与结果，`src/jobCache.ts` 保存浏览器中的最新查询。打开页面时恢复显示，继续读取由用户触发。
- `src/model.ts`：岗位规范化、严格条件校验、详情链接校验。
- `src/companies.ts`：有来源的企业参考名单，与岗位记录不同，不是岗位数据库。
- `src/bridge.ts` → `extension/content.js` → `extension/background.js`：版本化消息桥。扩展打开同浏览器 BOSS 标签页，在该页请求固定的只读岗位接口。
- `src/cities.ts`：复用原工程的城市代码。

不再启动官网专用的 8011 Python 服务。原网申控制台及其 8010、已有文件、历史岗位数据库与登录资料保持原位。旧官网 Python 读取路径已退役，没有并行回退。

## 行为与范围

- “学历要求”严格匹配岗位要求：选本科排除大专、硕士、学历不限和未披露；“本科及以上/统招本科”规范为本科要求。学历参数也传到 BOSS；即使平台返回扩展推荐，仍校验字段。
- 点击搜索一次提交全部条件；修改条件只影响下次搜索，不重新隐藏当前结果。平台支持关键词、城市、学历查询；行业等自定义条件在读到的记录中严格核对，未披露不视为匹配。招聘类型只采用披露或标题/经验明确指示，不把未知岗位推断成社招。
- 行业按明确的类别映射；人工智能行业与“AI 产品经理”岗位关键词并不等价。条件组合过窄可能没有结果，不能伪造符合条件的岗位。
- 默认每轮最多 10 页，可选 1/3/5/10/20/50；达到上限可继续。每次查询最多 500 页，重复页、登录/验证要求、网络错误、格式变化均停止并保留已读结果。不会绕过平台验证或宣称覆盖 BOSS 全站 90%。
- BOSS、智联提供浏览器实时读取，企业官网与人社查询已收录数据库。前程无忧、猎聘显示官方来源标识及暂未接入状态。企业官网使用“官网”文字图标。
- 点击“前往 BOSS”在当前浏览器打开对应 `/job_detail/<岗位ID>.html`；优先保留源链接，构造链接时带上原 securityId/lid。岗位失效或 BOSS 要求登录可能导致平台再次跳转，这不是官网主页跳转逻辑。
- 企业类别可重叠。国企参考国资委名录/明确披露，外企参考公司资料/明确披露；大厂、中厂、小而美是参考分组，不是认证。专精是产品服务聚焦，不等于专精特新资质。剩余企业归到“民企 / 小厂”浏览分组，未核实者标为“其他企业 · 待核实”。不靠品牌子串认定集团关系。
- 来源包括国资委央企名录、中国互联网协会综合实力报告、中国企业评价协会榜单、清华上市公司品牌报告及各企业官网。每项来源保存在 `src/companies.ts` 的参考条目中。当前首批名单有限，可扩充 aliases 和参考条目。
- 读取岗位和聊天记录无需模型 API Key。聊天记录使用浏览器只读通道，结果保存在网页内存。岗位结果和续读进度保存到当前网站的 IndexedDB。

## 权限与消息契约

Manifest V3，仅 `scripting` 与 BOSS/本地官网 host permissions。Chromium match patterns 不区分端口，因此另在 content script 和后台校验准确 origin（5186、自动化测试5197）、扩展ID、顶层frame和请求参数。

岗位读取与跳转使用 PING、OPEN_BOSS、PREPARE、FETCH_PAGE、FETCH_DETAIL、READ_METADATA，以及 OPEN_JOB、JOB_OPEN_STATUS、FOCUS_JOB 九种固定命令。READ_METADATA 只打开已校验岗位 ID 的后台详情页，并在读取结束或失败时关闭该临时页。OPEN_JOB 只接受 HTTPS 的准确 BOSS 岗位详情 URL，保留源链接访问参数；后两个命令仅接受本官网标签页所属的打开任务 ID。不能传入任意执行代码、任意域名目标或接口。BOSS 搜索优先复用同一窗口中独立打开的搜索标签页，并绑定到当前官网页；其他官网会话、隐身上下文、聊天/简历页不被接管。只有其他窗口的 BOSS 页时，会在官网窗口创建搜索页并沿用同一浏览器登录会话。后台在整个浏览器中限制一个读取任务，任务间隙通过心跳保留占用，防止另一个官网页改动搜索页面。数据回传只保留岗位字段；不读取/复制/发送账号 Cookie、密码、模型密钥。岗位 URL 自身的访问参数属于原岗位链接。

## 岗位跳转检查（0.4.8）

- 普通左键点击“前往 BOSS”或 BOSS 岗位标题，先停止当前网页的后续列表与详情读取，保留已有结果、条件和继续读取进度。扩展等待当前请求结束后再打开岗位；超过 20 秒未结束则提示稍后重试，不强行并发。再次搜索或明确恢复读取会重新建立读取状态。
- PING 声明 `job_navigation` 能力，网页复用已有连接检查结果，不因数据库列表翻页增加浏览器命令。新助手在原浏览器打开经过校验的完整岗位 URL，返回任务 ID。官网每 1.5 秒检查该标签页的 URL 与岗位区域是否已加载；检查只读取已打开页面，不再次请求 BOSS 接口。待验证/登录最多自动观察 2 分钟，回到官网窗口或点击“查看 BOSS 页面”可再次检查。普通加载超过 30 秒显示超时。
- 明确区分安全验证、登录、跳回首页、跳到其他页面、岗位关闭、加载超时和已打开详情。导航尚未提交时读取 `pendingUrl`，避免把重试前的首页误判成新的失败。不会把首页当成岗位详情成功，也不推断具体风控触发原因。
- 不自动刷新、循环重试或重复开标签页。同一岗位再次点击只聚焦已有标签页；用户明确点击重试时复用该岗位的标签页和完整源链接。若该标签页已关闭或被用户改为其他页面，则重新建页，保留用户其他页面。验证需要用户在 BOSS 完成；本功能不能解除平台验证，也不会打招呼或提交简历。
- 旧助手或 Ctrl/Command/中键等浏览器原生打开方式仍保留原链接，同时暂停官网后续读取，提示该方式不能回传打开结果。数据库岗位的官网跳转行为保持不变。
- 开发版沿用空闲自动更新，新版不增加扩展权限。跳转检查期间推迟自动重载，避免中断打开状态；已完成的内存记录不承诺跨扩展重载保存。0.4.8 引入此跳转检查，后续版本沿用同一能力标记。

## 实习类型与详情补全（0.3.0）

- 招聘类型为“不限”且关键词包含“实习”时，搜索提交会明确选中实习，向 BOSS 传入 `jobType=1902`。实际列表的实习类型是 `jobType: 4`，不可混用这两个编码；不再只靠职位标题判断。明确的其他招聘类型优先于关键词推断。
- 列表保留 `jobLabels`，识别“2027届”“26/27届”“2026-2028届”和标题“【2027校招】”。明确的毕业时间、标签和正文要求优先于标题年份，不用当前年份、项目或公司成立时间猜测。
- 0.4.6 起，每读取两页列表就自动补全这一批缺失详情，末批不足两页也会处理。列表仍逐页展示。列表已明确提供届数和截止时间的岗位直接复用，详情接口已给出所需信息时省略补充 HTML 请求。当前页面内保存页码、来源末页状态和已完成详情。中断后用户处理来源问题，点击恢复读取，先补未完成详情，再从失败页或下一页继续；来源已到末页时仅补剩余详情。本次搜索按岗位 ID 去重，排序和结果分页不会重复采集。部分信息读取失败在普通批次中不重试，只有用户明确恢复时再次处理。指定届数时，未知届数的候选岗位先保存在待核实集合及本地缓存中，核实匹配后才展示。刷新或关闭页面后可从 IndexedDB 恢复该进度。
- 详情请求逐个执行，不反复刷新 BOSS 标签页。列表发生登录/验证/网络错误后不再追加详情请求；详情被阻止时暂停并保留结果，不能宣称全部读取完毕。
- 新助手通过 PING 声明渲染核验能力及搜索页是否仍存在。常规详情成功返回、毕业时间仍缺失时，自动在同一浏览器后台打开该岗位，读取自身岗位区域的可见文字，再关闭临时标签页。验证、拒绝、身份不一致或跳转出现时暂停。用户明确恢复时，如果搜索页已关闭或离开，会重建搜索连接并保留页码和已读结果。旧助手继续使用原有详情能力，空闲更新后启用新能力。渲染核验会增加等待时间和页面加载量，不保证解除来源的访问限制。
- 岗位接口已成功返回、补充信息页仅发生一般网络或页面格式问题时，保留已有字段，继续其他岗位，本次搜索不重复请求该补充页。HTTP 401/403/429、明确验证或环境异常提示会暂停整轮读取。列表请求被拒绝后立即停止，不追加详情请求。整体进度区说明中断或补充信息缺失，当前内存结果仍可浏览。
- 表格中未读到的届数显示“未知”，截止时间未读到显示“无”；进度与中断原因只在整体状态区展示。截止时间只取明确招聘截止信息或同一岗位 JobPosting 的 `validThrough`，不取发布日期、页面更新时间、HR 活跃时间或抓取时间。
- 助手读取 `.job-detail-section .school-job-sec` 的独立校招信息栏，兼容“毕业时间：2027年”和“招聘截止日期：2027.06.30”。元数据解析清理标签中夹入的固定来源文字及零宽字符。2026-11-08 已在实际登录浏览器核验普通校招岗位和猎头发布的“【2027校招】AI Agent技术开发岗”。当前执行顺序以本节 0.4.6 行为为准。

## 自动连接与版本更新（0.4.0）

- 不再把 `openerTabId === 当前官网标签页 ID` 当作唯一连接条件。PING 检查同一浏览器上下文已打开的 BOSS 页面，PREPARE 自动选择或建立搜索页；是否登录由 BOSS 实际响应确认，不将“标签页存在”等同于已登录。
- 网页兼容 0.3.x 助手的旧绑定逻辑：误报未连接时，搜索自动调用 OPEN_BOSS 修复绑定，无需用户先更新或再次点击连接。0.2 及以下不支持详情功能，无法仅靠网页补上扩展中不存在的能力，需由维护人员迁移。
- 本地开发包的 `version_name` 以 `-local` 结尾。开发者修改代码时必须同时提升 `manifest.json` 的 version；助手在空闲时读取自身目录 manifest，发现新版本后自动 reload。更新能力首次引入前的旧包不能自行加载这段新能力，但 0.3.x 可继续使用上述网页兼容路径。
- 任务期间通过 PING 的 busy 心跳和请求租约推迟 reload，读取完成后才应用更新。onInstalled 为已打开的官网重新注入桥接脚本；不刷新官网，不清除搜索结果。桥接脚本替换旧监听器，网页同时兼容更早版本留下的失效监听器。
- 正式发行必须移除 `version_name` 中的 `-local` 标记，配置真实官网域名并发布到 Chrome Web Store / Edge Add-ons；商店签名包由浏览器检查和下载更新，本地开发目录不能冒充商店更新。已接入 runtime.onUpdateAvailable，空闲时应用已下载版本。仓库尚未上架商店，不能宣称现有用户已接入正式自动分发。不会从远程下载并执行脚本以绕过商店审核。
- 官方参考：https://developer.chrome.com/docs/extensions/develop/concepts/extensions-update-lifecycle

## 校招与中途连接恢复（0.4.1）

- 选择校招时，官网在关键词未含“校招/校园招聘/应届”时追加“校招”后交给 BOSS 搜索，再核对结果。未使用未经确认的校招数字接口参数，也不宣称接入了独立校园招聘接口。明确“应届生/应届毕业生/在校/应届”的岗位可进入校招结果，实习类型、明确社招仍分别处理。该逻辑也适用于 0.3.x 助手。
- 0.3.x 在翻页或开始读取时若返回其明确的“标签页绑定缺失”错误，官网最多恢复一次，继续同一页，不清空结果。登录验证、平台拒绝、网络错误均不自动重试；恢复失败会说明搜索连接中断，不再一律归因于未登录。
- 新助手允许已绑定搜索页移动到同浏览器的另一窗口，仍隔离其他官网会话和隐身窗口；搜索页关闭或改变时准确提示连接状态。岗位列表同时显示 BOSS 返回条数和符合条件岗位数，零匹配不再等同于没有读到数据。
