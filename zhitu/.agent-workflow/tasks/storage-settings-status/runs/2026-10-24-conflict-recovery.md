# 本地差异处理与移动菜单调整（2026-10-24）

## 已核实的原因

- 对用户指定目录只读核对清单与内容哈希：学习规划清单有 3 个文件与记录不同，简历记录一致；不输出正文，不修改用户文件。哈希差异只能说明文件与记录不一致，不能断言由手工修改造成，旧记录不同步也可能触发。
- 旧 `flush()` 只处理新快照，相同快照沿用 `written/conflicts`；手工恢复文件后，界面的“立即保存副本”仍可能不重新检查。
- 新增回归在旧实现上失败：`manual recheck must inspect disk, not retain an old conflict forever`，实际为 conflict、预期 saved。

## 实现

- `flush(true)` 提供显式磁盘重查，自动保存继续使用原有队列，真实未解决差异不会被静默关闭。
- 设置页新增“处理本地差异”。弹窗解释记录不一致并展示所选目录和账号；取消不写文件。用户确认“保留原件并恢复备份”后，先将有差异原件以二进制 Blob 复制到带 `--电脑原件-` 的独立文件，核对字节，再以当前平台内容更新标准备份和清单。
- 原有平台副本、其他文件和旧原件副本均不删除、不覆盖；同名保留副本被改动时另选编号，不覆盖。BOM、换行及原始编码通过按字节复制保留。
- 确认绑定到当时目录状态及快照签名。切换目录/账号、状态变化、保存副本失败、处理期间文件再次变化时不沿用旧确认；错误后需重新检查确认。保存队列串行执行，不反向上传电脑文件。
- 警告文案不再断言“被手工修改”，说明可通过处理入口恢复正常备份。
- Sidebar 删除文件/文件夹的“移动到…”菜单、菜单处理函数及递归透传参数，保留原拖拽移动、批量移动校验和 Agent 有效权限变化确认。

## 边界

- 未在真实用户目录执行差异处理，原生系统目录选择仍由用户操作。恢复是当前本地备份处理，不是本地笔记反向导入、跨应用原子事务或永久忽略后续差异。
- 保留既有未提交工作，不提交、推送；不修改 AI 助手或正式数据库。既有用户开发服务保留，仅清理本次测试服务。
